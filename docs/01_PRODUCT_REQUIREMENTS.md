# SketchToUI 产品需求文档

> 状态：持续维护
>
> 更新日期：2026-07-13
>
> 本文汇总当前已确认的产品、解析、画布、MCP、账号与后续商业化需求。实现任务应以本文的优先级和验收标准为准；未明确列出的功能不能默认加入产品范围。

## 1. 产品定位

SketchToUI 是面向既有 Sketch 设计稿的 Web 平台与 Remote MCP 服务：用户导入 `.sketch` 文件后，可在浏览器中检查页面、图层、属性和资源；再让 Codex、Cursor 等外部 AI 编码工具通过 MCP 精确读取指定设计上下文，用于还原前端页面。

核心价值不是销售 AI Token，也不是保证 AI 自动生成代码的质量，而是提供：

- 可验证的 Sketch 页面、图层和视觉上下文；
- 画板预览、图片、SVG/图标、文本样式和设计 Token；
- 仅访问当前用户已授权项目的 Remote MCP；
- 让外部 AI 更准确地理解存量 Sketch 设计稿。

## 2. 范围、优先级与术语

### 2.1 优先级

| 优先级 | 含义 |
| --- | --- |
| P0 | 核心闭环，影响导入、画布准确性、用户数据隔离或 MCP 可用性，必须优先完成。 |
| P1 | 显著提升 AI 还原价值、可用性和产品留存，应在 P0 稳定后完成。 |
| P2 | 商业化、团队化或运维增强；不应阻塞核心功能验证。 |

### 2.2 术语

| 术语 | 定义 |
| --- | --- |
| 项目 | 用户导入的一份 Sketch 文件及其解析结果、资源与版本。 |
| 页面分组 | `meta.json → pagesAndArtboards` 中的一个 Sketch 页面元数据分组。其 UUID 可关联 `document.json`、`user.json` 与 `pages/<page-id>.json`。 |
| 设计页面 / 画板 | 页面分组中的 Artboard；是画布展示、MCP 读取和前端还原的主要单位。 |
| 图层 | 画板内部的 text、shape、group、symbol、image 等节点。 |
| 电脑端 / 移动端 / 插件版 | 左侧目录的一级分类，而不是普通图层分组。 |
| 设计上下文 | 画板结构、样式、文本、资源、预览、Token、组件摘要等可供 AI 读取的数据。 |

## 3. 当前产品边界

### 3.1 当前必须做

- 单用户注册、邮箱验证、登录、项目管理和 Sketch 导入；
- 高保真解析和可交互画布；
- Remote MCP、MCP Token 与跨用户数据隔离；
- 画板预览、图片/图标资源、设计 Token、组件摘要；
- 面向个人开发者的低价会员能力预留。

### 3.2 当前明确不做

- 内置 AI Token 售卖、承诺 AI 生成页面质量或强制使用某一家模型；
- OAuth 登录授权流与动态客户端注册；当前 MCP 使用手工创建的 Bearer Token；
- 团队协作、企业版、私有化部署与复杂组织权限；
- Docker 作为唯一部署方式；原生部署可行；
- 复杂 Token 生命周期、自动过期策略或按用户细粒度计费；
- “Plus AI 生成套餐”。将来可以接入用户自有 AI Provider，但不是当前范围。

## 4. 用户与核心闭环

### 4.1 用户角色

| 角色 | 目标 |
| --- | --- |
| 访客 | 注册并验证邮箱。 |
| 已验证用户 | 导入、查看、管理自己的 Sketch 项目，创建并管理 MCP Token。 |
| 外部 AI 客户端 | 使用用户提供的 MCP Token，仅读取该用户允许访问的项目与资源。 |

### 4.2 核心验收闭环（P0）

```text
导入真实 Sketch 文件
  → 正确按电脑端 / 移动端（H5）/ 插件版归类
  → 选择页面分组与画板，画布视觉接近原始预览
  → 在画布或图层树选中图层，右侧只展示该图层自身数据
  → 复制该画板 MCP Resource
  → Codex/Cursor 读取预览、资源、文本与设计 Token
  → 外部 AI 可据此实现接近设计稿的 React 页面
```

## 5. 账号与认证

### 5.1 注册与登录（P0）

- 采用用户名、邮箱、密码注册；用户名唯一、邮箱唯一。
- 邮箱验证码仅保存在带 TTL 的缓存（默认内存，可选 Redis），不创建“邮箱验证码”数据库表。
- 验证码有效期 10 分钟；发送按钮有 60 秒倒计时和重发冷却。
- 注册、验证码输入与验证应在同一认证卡片内完成，不跳转到另一页面或路由。
- 发送成功、失败、注册成功等状态应使用页面顶部 Toast/消息提示，而不是挤入表单正文。
- 密码输入框提供“显示/隐藏密码”的小眼睛按钮。
- 前端必须安全处理非 JSON 错误响应，不能将 HTML 错页直接作为 JSON 解析。
- 用户验证邮箱后才允许导入项目、读取项目资源和创建可用 MCP 配置。

### 5.2 Session 与安全（P0）

- 登录 Session 存在所选缓存，自动过期；退出登录后立即删除 Session。默认内存模式下重启会失效，多 Web 进程部署使用 Redis 共享会话。
- Cookie 使用 `HttpOnly`、HTTPS 生产环境下 `Secure`、`SameSite=Lax`。
- 所有项目、资源、MCP Token 操作均必须从当前 Session / Bearer Token 派生用户 ID，禁止信任客户端传入的用户 ID。

## 6. 项目导入、解析与管理

### 6.1 Sketch 文件处理（P0）

- `sketch_to_json.py` 的输入方式不变：将 `.sketch` 文件复制为 `.zip` 后解压至指定目录。
- 上传后保存原始 Sketch 文件、解压后的数据、图片资源、Canvas JSON 和预览相关数据。
- 导入过程中显示上传、解压、解析、生成画布的实时进度、百分比和失败原因。
- 导入完成后自动进入对应项目的画布；项目首页默认是“项目管理”，而不是登录页或固定单项目画布。
- 支持多个项目的创建、打开、删除和重新导入；删除时同步清理对象存储中该项目的相关内容。
- `docs/` 只放文档；测试 Sketch 样本应放在 `fixtures/`，不再把测试/解析产物当作文档内容。

### 6.2 页面分组与目录规则（P0）

左侧目录必须以平台为第一层级：

```text
电脑端
  登录
    注册页
    登录页
  设置
移动端（H5）
  首页
  登录
插件版
  插件页面或其设计页面
```

- `meta.json → pagesAndArtboards` 的页面元数据用于定位 Sketch 页面与其 Artboard。
- Artboard 名称以 `H5` 开头的，归入“移动端（H5）”。
- Sketch 页面名称为“插件”或“插件版”的，归入“插件版”；它与“电脑端”“移动端（H5）”同级，不能误归到电脑端。
- 空 `pagesAndArtboards` 分组不显示在目录中。
- 目录展示各层数量；页面分组区域可展开、收起、滚动，不能因固定高度导致可见区域过小。
- 图层目录只展示当前选中设计页面的图层；不显示其他画板或无关分组。
- 页面分组、设计页面和当前画布选择状态需要保持一致，切换鼠标焦点或关闭面板时不能重置画布位置或跳到其他对象。

### 6.3 项目版本（P1）

- 每次重新导入保存导入时间、源文件哈希、解析版本和当前版本标记。
- MCP 返回项目导入版本与更新时间，避免 AI 基于旧设计上下文继续工作。
- 后续支持版本差异摘要；不要求当前阶段实现完整可视化 Diff。

## 7. 画布与图层检查器

### 7.1 画布交互（P0）

- 画布、图层树、右侧数据检查器必须职责分离，不能以 Python 静态页面替代 React 交互画布。
- 画布支持鼠标拖拽平移、滚轮/快捷键缩放、适应窗口、缩放百分比显示与快捷键提示。
- `Ctrl + 鼠标滚轮` 应缩放画布，不应缩放浏览器页面。
- 鼠标移出、选择页面、展开目录或右侧面板开关时，画布缩放与平移位置必须稳定，不能恢复初始比例或跳转到错误图层。
- 支持从画布直接点选图层；画布点击、左侧图层树与右侧检查器三者同步高亮。
- 鼠标悬停图层时显示名称、类型、位置、尺寸等轻量信息；悬浮提示不得阻碍点击。
- 选中状态显示边框、尺寸、坐标、PX 标注、参考线/网格等设计工具风格信息。
- 非画布区域（顶部栏、左右侧栏）的比例应紧凑；画布应获得最大可用空间。
- 大型项目中图层树使用虚拟列表，避免数千层导致左侧目录卡顿。

### 7.2 右侧属性检查器（P0）

- 只展示当前选中图层自身的 JSON/结构化数据；不得递归展示全部子图层。
- 至少显示：名称、类型、Sketch 类型、对象 ID、可见性、锁定状态、旋转/翻转、X/Y、宽高、不透明度。
- 文本图层额外显示：文本内容、字体、字号、字重、颜色、对齐方式、行高、字距、段落/垂直对齐信息。
- 视觉框与原始 `sourceFrame` 必须同时可查，便于判断“源数据正确但渲染位置不正确”的问题。

### 7.3 性能与稳定性（P0）

- Canvas 渲染、命中测试、选中框和悬停信息应保持平滑；避免 state 更新导致视口重复重置。
- 页面分组/画板切换应取消过期请求，避免旧请求覆盖新页面选择。
- 大型 Canvas 数据按页面分组加载，不能一次加载所有画板的完整图层树。

## 8. Sketch 解析与视觉还原

### 8.1 数据关联与开发分析工具（P0）

- 支持从 `pagesAndArtboards → page UUID → artboards → artboard UUID` 精确抽取“一个目标设计页面”的全部关联数据。
- 页面 UUID 可关联 `meta.json`、`document.json`、`user.json` 与 `pages/<page-id>.json`；输出时不得混入无关页面/画板数据。
- 原始页面文件里某些节点可能为 `_class: group`，但页面归属应以 `meta.json → pagesAndArtboards` 的 Sketch 页面语义判断，不能误判为普通图层分组。
- `sketch_to_struct.py` 用于提取和分析指定页面/画板；应生成便于人工检查的 `.parsed.json`。

### 8.2 渲染准确性（P0）

- 原始 `previews/preview.png` 是重要的视觉参考；画布和 MCP 预览都应以其作为回归比对依据。
- 文本不能统一按视觉框或 CSS 默认方式强制垂直居中；必须综合 `sourceFrame`、文本 Run、行高、段落对齐和垂直对齐信息渲染。
- 必须保留文本 Run 的字体、字号、字重、颜色、对齐、行高、字距、大小写等字段，便于导出 CSS 与 AI 读取。
- Shape Path 必须解析点、曲线控制点、闭合路径、fill/border 等信息，并尽量转换为正确 SVG Path；不能把球形图标、曲线路径渲染成直线或错误形状。
- Symbol、图片填充、位图、基础图标必须优先引用对应资源；只依赖 Path JSON 不能完整复现时，需要以资源或预览为补充。
- 支持 fills、borders、shadows、corner radii、opacity、rotation、翻转、裁剪和常见 blend mode 的合理还原。
- 图层重叠检测使用视觉框并返回判断依据；结果应与 Sketch/预览中的实际视觉关系一致，不能仅因嵌套或坐标系错误出现误判。

### 8.3 已知回归样本（P0）

下列样本用于持续验证解析、文本与 Shape Path 还原，不能在后续改动中回归：

| 对象 ID | 关注点 |
| --- | --- |
| `1008A54F-60FE-4D2D-BE9C-2EB5187AEE7C` 与 `F15E40FD-5EB1-47FA-B202-3EAD09115CF9` | 重叠检测应与真实视觉展示一致。 |
| `44C8916C-FE6F-4E2F-AF7B-24FB8620FF00` | 文本内部水平/垂直对齐检查。 |
| `F2EE4382-4CFA-48DF-8A25-5D80EED47760` | `请设置8-20位密码，需要包含大小写字母与数字` 的字体、行高、左对齐与视觉位置。 |
| `20B4EA36-B7DC-496B-A0DC-A73864AD0C87` | `请输入您的公司` 的文本框、14px 字体与视觉垂直位置。 |

## 9. Remote MCP

### 9.1 连接与 Token（P0）

- MCP 为独立的 Remote Streamable HTTP 服务。
- 用户在 Web 平台创建 `skt_...` Token，并手工写入 Codex/Cursor 的 Remote MCP 配置；当前不做 OAuth 登录授权流。
- Token 只需要支持创建、查看、复制、启用、禁用和撤销。
- 不要求 Token 有效期、最大数量、复杂生命周期或按 Token 计费；默认 Token 不自动过期。
- Token 只能读取该 Token 所属用户的项目；任何项目 ID、分组 ID、Artboard ID、资源路径都必须再次校验用户归属，绝不允许跨用户访问。
- 优先保证全局高并发场景的 Redis 限流与服务稳定性；用户读取自己的数据不应被不必要地限制。
- 记录最少必要的 Token 使用信息：最近使用时间、请求工具、失败原因；复杂审计平台可后置。

### 9.2 MCP 必须提供的设计能力（P0/P1）

| 能力 | 优先级 | 说明 |
| --- | --- | --- |
| `list_projects` | P0 | 列出当前 Token 可访问项目。 |
| `list_page_groups`、`list_artboards` | P0 | 发现平台分组、页面分组和设计页面。 |
| `get_design_context` | P0 | 使用 `sketchtoui://` Resource 有限深度读取上下文。 |
| `find_layers`、`get_layer` | P0 | 按名称、类型、文本检索，或只读取一个图层自身数据。 |
| `inspect_text_layout`、`check_overlap` | P0 | 辅助排查文本和视觉布局问题。 |
| `get_artboard_preview` | P0 | 返回画板 PNG；AI 必须能看到真实视觉参考。 |
| `get_design_asset` | P0 | 返回图片、图标等私有设计资源。 |
| `get_design_tokens` | P1 | 汇总颜色、字体、字号、圆角、阴影、间距。 |
| `list_reusable_components` | P1 | 发现重复分组、Shape Group、Symbol 组件候选。 |
| 项目/分组/画板/图层 Resource | P0 | 支持 `sketchtoui://projects/...` 自然发现与精确读取。 |

### 9.3 前端 MCP 体验（P1）

- 当前画板提供“一键复制 MCP Resource 链接”。
- MCP 管理页展示 Remote MCP URL、Token、状态、最近使用时间与启用/禁用操作。
- 给用户提供按画板、图片资源、设计 Token、组件摘要的使用指引和提示词模板。
- 产品只提供设计上下文；外部 AI 的模型选择、计费与代码质量由用户的 Codex/Cursor/Provider 决定。

## 10. 项目资源、预览与设计系统

### 10.1 预览和资产（P0）

- 每个画板都能生成或读取 PNG/WebP 预览；MCP 可返回图片，而不只是 JSON。
- MCP 资源访问使用 Bearer Token 权限，不依赖浏览器 Cookie。
- 图片、SVG、图标、bitmap fill 等资源必须能被定位、读取并关联到引用它们的图层。
- 对象存储 Bucket 必须私有；资源通过已鉴权接口或短时签名 URL 暴露，不能泄漏其他用户文件。

### 10.2 设计 Token 和组件摘要（P1）

- 自动汇总全项目或单页面分组的：颜色、字体、字号、字重、行高、圆角、边框、阴影和常用间距。
- 识别重复出现的 Symbol、分组和形状组合，输出组件候选及出现次数。
- 这些摘要用于帮助 AI 生成风格一致的 React / MUI / Ant Design / Tailwind 页面，不替代原始图层数据。

## 11. 后续个人版商业化（P2）

商业化建立在“解析可信、画布可用、MCP 可帮助外部 AI 还原页面”之后，不应优先于核心功能。

| 套餐 | 价格 | 计划权益 |
| --- | --- | --- |
| 免费版 | ¥0 | 2 个项目、500 MB、基础画布、基础图层数据、1 个 MCP Token。 |
| 个人会员 | ¥9/月 或 ¥96/年 | 20 个项目、10 GB、完整 MCP、预览图、图片/SVG/图标资源、设计 Token、组件摘要、导出、30 天版本记录。 |

- 不销售平台自有 AI Token；不以“AI 自动生成页面”作为当前套餐权益。
- 将来可接入用户自有 AI Provider，提供上下文打包、工作流和代码导出，但不承诺外部模型输出质量。
- 支付采用第三方支付服务：后端创建订单、第三方完成付款、支付回调验签后开通会员；前端成功页不得直接开通权益。
- 初期可采用用户主动月付/年付续费，不需要自动代扣订阅。

## 12. 技术与数据约束

- 前端：React + TypeScript + MUI；生产页面应优先 React 交互体验。
- 后端：Flask；MCP：独立 Uvicorn Streamable HTTP 服务。
- 数据库：开发可用 SQLite，生产迁移至 MySQL；数据库结构升级使用 Alembic。
- 缓存：默认进程内内存，可选 Redis，保存 Session、邮箱验证码、重发冷却、导入进度与限流；多实例使用 Redis 共享状态。
- 文件存储：默认本地 `data/storage`，可选 MinIO，保存源 Sketch、解压数据、资源和 Canvas JSON；Web 与 MCP 共享同一存储。后续对接 OSS 时必须完成兼容性验证。
- 大文件解析应最终使用 Redis 驱动的独立 Worker；不能长期依赖 Web 服务进程内线程。
- 生产环境使用 HTTPS、反向代理和原生进程守护；Docker 不是当前强制要求。

## 13. 不变量与验收要求

- 用户 A 的 Web Session 或 MCP Token 绝不能访问用户 B 的项目、画板、图层或图片资产。
- 无关页面、画板、图层不能混入“指定 UUID 抽取结果”。
- 选择画板后，画布不得自动跳转到其他对象或重置缩放/平移。
- 右侧检查器不得递归展示当前图层的所有子节点。
- 预览图、资源读取与结构数据必须可共同用于判断视觉效果；JSON 不足以复现时需保留视觉资源作为上下文。
- 新需求应先补充本文的优先级、边界和验收标准，再进入实现。

## 14. 建议实施顺序

1. P0：修复视觉渲染、文本、Path/SVG、资源引用、画布选择与视口稳定性。
2. P0：完善目标页面抽取、平台目录、项目管理、导入进度和当前画板图层树。
3. P0：确保 MCP 的预览、资产、用户隔离、Token 启停和高并发限流可用。
4. P1：补设计 Token、组件摘要、版本标识、MCP 使用指引与画板快捷复制。
5. P2：根据真实使用数据接入会员、第三方支付、用量统计和存储配额。
